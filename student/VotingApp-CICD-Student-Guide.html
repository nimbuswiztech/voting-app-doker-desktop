3. Prerequisites and safety

Recommended: 16 GB RAM allocated to Docker Desktop, 4 CPU cores and 20 GB free disk.

kubectl config current-context
kubectl get nodes -o wide
docker version
docker compose version
docker ps -a --format 'table {{.Names}}\\t{{.Image}}\\t{{.Status}}'

Both nodes should be Ready. Enable Docker Desktop → Kubernetes → Show system containers (advanced) if necessary so Docker CLI can see the node containers.

Security: Jenkins mounts the Docker socket and has a kubeconfig. Jobs can control Docker and access the cluster. Keep Jenkins local, do not expose it publicly and do not run untrusted pipelines.

5. Jenkins setup

  1. Open Jenkins at port 8080.
  2. Retrieve unlock password with ./scripts/jenkins-password.sh.
  3. Complete setup wizard and install suggested plugins.
  4. Create Pipeline job votingapp-cicd.
  5. Choose Pipeline script from SCM → Git → your project repository.
  6. Set Script Path to jenkins/Jenkinsfile.
  7. Save.

Verify connectivity:

./scripts/check-jenkins-k8s.sh

6. SonarQube setup

  1. Open SonarQube port 9000.
  2. Fresh install: admin/admin; change the password.
  3. Create project key voting-app-training.
  4. Generate a user token.
  5. Jenkins → Credentials → add Secret text credential with ID sonarqube-token.

Scanner uses sonar.qualitygate.wait=true so it waits for the quality gate. No webhook is needed in this pipeline.

8. Why import images into both nodes?

Docker builds images in the Docker daemon. Kubernetes nodes use containerd. They are separate image stores, so a locally built image is not automatically available to the cluster.

Docker buildvoting-vote:tag
docker saveImage archive stream
ctr importControl plane
ctr importWorker
docker exec desktop-control-plane ctr -n k8s.io images ls
docker exec desktop-worker ctr -n k8s.io images ls
This method requires node containers to be visible to Docker CLI and ctr to be present inside each node. The project preflight checks visibility; the connectivity helper checks ctr. If unavailable, use a registry reachable by the cluster instead. Do not reset your cluster.

11. Troubleshooting

Jenkins cannot connect to Kubernetes API
kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}{"\\n"}'
docker exec voting-jenkins kubectl config current-context
docker exec voting-jenkins kubectl get nodes

API endpoint must be reachable from Jenkins and TLS certificate validation must succeed. Do not disable TLS verification.

Docker cannot inspect node containers

Enable Show system containers (advanced), then:

docker ps -a | grep -E 'desktop-control-plane|desktop-worker'
docker inspect desktop-control-plane
ctr missing in node
docker exec desktop-control-plane ctr version
docker exec desktop-worker ctr version

If unavailable, switch to a cluster-reachable registry delivery method; do not reset the cluster.

ErrImageNeverPull
kubectl describe pod -n votingapp <pod-name>
docker exec desktop-control-plane ctr -n k8s.io images ls | grep voting-
docker exec desktop-worker ctr -n k8s.io images ls | grep voting-

Exact image tags must exist in both nodes.

SonarQube is slow or unhealthy
docker compose logs -f sonarqube
docker compose logs -f sonardb

Increase Docker Desktop memory allocation if needed.

13. Trainer speaking script

Opening

“Jenkins orchestrates the delivery. SonarQube checks source quality. Docker builds images. Kubernetes runs the application.”

Critical concept

“A Docker image in the Docker daemon is not automatically present in the containerd store used by Kubernetes nodes. Our pipeline transfers each image to both nodes before deployment.”

Production extension

“In production we would add a secured registry such as JFrog, secret management, persistent storage, ingress, resource limits, approvals and a hardened CI server.”

Completion criteria: Pipeline succeeds, quality gate passes, app pods become Ready, and Vote and Result UIs respond through port-forward.
